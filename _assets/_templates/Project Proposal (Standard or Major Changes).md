## Purpose
This section should clearly and concisely define the issue or need being addressed. Provide a high-level overview of the problem, its impact, and the intended outcome of the project. The purpose statement should answer why this project is necessary and what it aims to achieve.

Define the type of change: Standard/Minor, Major, or Emergency

> [!Note] Example Phrasing
> *Edit the following text with your specific scenario*
> 
> The purpose of this proposal is to address \[issue/need\] by implementing \[general solution\]. This initiative seeks to improve \[efficiency/security/reliability/etc.\] within the IT environment and align with organizational goals of \[relevant objectives\].

## Issues
This section should outline the evidence supporting the need for the project. Link any issues contained in the [[Issues]] folder. 

These recurring issues underscore the necessity for a structured and sustainable solution.

> [!Bug] Example Phrasing
> *Edit the following text with your specific scenario*
> 
> Current observations indicate that \[problem description\]. 
> For instance:
>- \[Issue 1: describe clearly, include metrics if available\]
>- \[Issue 2: describe clearly\]
>- \[Events or incidents that have highlighted the need\]

## Scope
Define the boundaries and reach of the project. Clarify the systems, users, and processes that will be impacted. Identify any dependencies, related projects, or teams involved. This scope ensures that all stakeholders understand the breadth of the project and potential downstream impacts.

> [!Abstract] Example Phrasing
> *Edit the following text with your specific scenario*
> 
> The scope of this project includes:
> - \[Systems or platforms affected\]
> - \[Departments or user groups impacted\]
>- \[Integration with existing or planned projects\]
>- \[Operational or procedural changes\]

## Discovery
If appropriate, ensure discovery is done and documented as an individual.

Proposed changes are analyzed and documented before moving forward. All changes categorized as standard, major, or emergency. 

Testing results, expectations, limitations, and any required migrations or dependencies must be identified to ensure the change is feasible, low-risk, and aligned with organizational goals.

## Proposed Solution
Detail the recommended course of action, broken down into clear, actionable steps. This section should illustrate how the solution resolves the identified issues and provide a road-map for implementation.

This structured approach ensures effective resolution of the identified issues and supports long-term operational stability.
